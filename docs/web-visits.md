# Заходы на сайт (свой счётчик, раздел «Заходы на сайт» в CRM)

Решение 14.11.2026: в админке видно, кто и откуда заходил на сайт, что смотрел и нажимал, человек это или бот,
была ли с захода заявка. Без записи экрана: для неё остаётся Вебвизор Яндекс Метрики (ClientID есть у захода).
Устроено по образцу счётчика «Сто дорог» (их docs/visits-api.md).

| Часть | Где |
|---|---|
| Счётчик на страницах, связь формы с заходом | `sites/vdokh-lab/src/assets/js/main.js` (блок `VT`), политика — `src/pages.js` |
| Приём данных | `src/app/api/public/visits/route.ts`, `src/lib/web-collect.ts` |
| Источник, устройство, бот | `src/lib/web-detect.ts` |
| Таблицы | `web_visits`, `web_pages`, `web_events`, `leads.visitor_id` (миграция `drizzle/0002_web_visits.sql`) |
| Админка | `/traffic` (сводка и список), `/traffic/[id]` (заход), блок «Путь клиента» в карточке лида |

Таблицы называются `web_*`, потому что `visits` — выезды техников.

## Путь данных

Сайт → `POST /api/visit` на своём домене (`navigator.sendBeacon`, `text/plain`) → nginx добавляет `X-Site-Key` (тот же
ключ, что для заявок, из `LEAD_KEYS`) и `X-Site-Host` → `POST /api/public/visits` в CRM. Ответ всегда `204`.
Не больше 8 КБ на запрос, 50 сообщений в пачке, 120 запросов в минуту с IP. Запрос со страницы чужого домена отбрасывается.

nginx на домене сайта (рядом с `location = /api/lead`):

```nginx
location = /api/visit {
    proxy_pass http://127.0.0.1:3100/api/public/visits;
    proxy_set_header X-Site-Key <ключ сайта из LEAD_KEYS>;
    proxy_set_header X-Site-Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 16k;
}
```

## Cookie и сообщения

`ar_vid` — посетитель, 22 случайных символа, 12 месяцев. `ar_sid` — заход: 30 минут бездействия, новый при переходе
с другого сайта или с новыми utm-метками. `pid` — просмотр страницы.

- `view` — открыта страница: путь (из строки запроса только utm_*, yclid, gclid, fbclid), заголовок, откуда (чужой сайт —
  без строки запроса), utm, экран, язык, часовой пояс, сенсорный экран, `navigator.webdriver`, ClientID Метрики.
- `event` — `tel` (номер), `wa`, `form_open`, `form_view`, `form_start` (значения полей не отправляются), `form_error`,
  `lead` (номер заявки), `scroll` (25/50/75/100), `out` (хост), `file`, `scent` (аромат), `model` (аппарат), `faq` (вопрос), `osi`.
- `ping` — раз в 30 секунд, пока вкладка видна («Сейчас на сайте» — ping за 2 минуты).
- `leave` — вкладку скрыли или ушли: секунды на экране и наибольшая прокрутка.

Форма заявки отправляет `visitor_id` и `visit_id`; сервер ставит `leads.visitor_id` и `web_visits.lead_id`.

## Что считает сервер

- Источник по первому просмотру: yclid → Яндекс Директ, gclid → Google Реклама, utm_source → «Реклама: …», затем по
  адресу перехода: поиск Яндекса / Google / Bing, Яндекс и Google Карты, 2ГИС, соцсети и мессенджеры, ИИ-помощники,
  «Сайт: хост», пусто — «Прямой заход». Группы и цвета — `SOURCE_GROUPS`.
- Бот: подпись робота или скрипта (в т. ч. HeadlessChrome), `navigator.webdriver`. Подозрительно (после конца захода):
  больше 30 страниц за 5 минут, страница ни разу не была на экране, меньше 2 секунд без действий. Боты в списке скрыты.
- Раз в 10 минут (при приёме данных): окончательная классификация законченных заходов и удаление заходов без заявки
  старше 90 дней. Заходы с заявкой живут, пока есть заявка.

## Кто видит

Собственник, руководитель продаж, маркетолог (раздел `traffic` в `lib/access.ts`): в заходах есть IP.
«Путь клиента» в карточке лида видят все, кто видит лида; ссылки на заходы — только с доступом к разделу.
