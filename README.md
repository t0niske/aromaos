# AromaOS

Система управления аромамаркетингом (Астана): лиды → клиенты → объекты → подписки, сервисные визиты, оборудование, задачи. Реализует MVP-ядро из спецификации `aroma-marketing/docs/05-business-system.md`.

**Статус:** v0.1, разработка. К сайтам (Tynys, ÁUA, ВДОХ, HOSH) **не подключена** — приём заявок готов, но сайты на него ещё не смотрят.

## Запуск

```bash
npm install
cp .env.example .env.local        # и задать SESSION_SECRET
npm run db:seed                   # демо-данные (сервер должен быть остановлен)
npm run dev                       # http://localhost:3000
```

Без `DATABASE_URL` работает встроенный PostgreSQL (PGlite) в `data/pglite` — ставить ничего не нужно. PGlite однопроцессный: наполнение и сервер не запускать одновременно. Если после аварийной остановки база не открывается — `npm run db:reset` (пересоздаёт демо-базу).

Демо-входы (только для локальной разработки) — в шапке `src/db/seed.ts`: собственник, два менеджера продаж, руководитель сервиса, техник.

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки |
| `npm run build` | продакшен-сборка |
| `npm run db:seed` / `db:reset` | демо-данные / пересоздать базу |
| `npm run db:generate` | новая миграция после правки `src/db/schema.ts` |
| `npm run typecheck`, `npm run lint` | проверки |

## Что есть

| Раздел | Возможности |
|---|---|
| Дашборд | MRR/ARR, новые подписки за месяц, сделки в работе, конверсия, визиты сегодня и просрочки, продления в 30 дней, оборудование, воронка, источники лидов по сайтам, мои задачи |
| Лиды и продажи | канбан с перетаскиванием по этапам (Новый → Квалификация → Замер → Тест → КП → Договор → Выиграно/Проиграно), список с поиском и фильтром по сайту, карточка: история, заметки, задачи, правка данных, «Выиграть» с выбором тарифа |
| Клиенты | компании (ТОО/ИП/АО, БИН, НДС, госсектор), контакты и ЛПР, объекты, MRR и сумма договоров, средняя оценка визитов |
| Объекты | зоны с ароматами из коллекции (32 аромата), аппараты, подписка (оформить, продлить, пауза, расторгнуть), визиты (план и история), параметры для техника |
| Подписки | действующие, на продлении, пауза/тест, расторгнутые; MRR по моделям, причины оттока |
| Визиты | сегодня / неделя / просрочено / выполнено; карточка визита для телефона техника: чек-лист, масло, оценка, перенос |
| Оборудование | реестр Nova 300 / Nova 1000 по статусам, приёмка, перемещения и история, QR-наклейка на карточку, окупаемость |
| Задачи | мои / все / выполненные, просрочки, привязка к лиду и объекту |
| Настройки | команда и роли, тарифы из прайса, ключи сайтов для приёма заявок, проверка продлений, журнал действий |

**Роли** (`src/lib/access.ts`): собственник видит всё; продажи — лиды, клиенты, объекты, подписки; сервис — объекты, визиты, оборудование; техник — только свои визиты, оборудование и задачи.

**Автоматизации** (`src/lib/domain.ts`):
- новый лид → ответственный (у кого меньше открытых) + задача «связаться за 15 минут»; дубль по телефону → в историю открытого лида;
- этап «Тест» → задача позвонить за день до конца;
- выигрыш → клиент, контакт, объект, подписка, график визитов на весь срок, аппарат со склада, 3 задачи онбординга; задачи продажи закрываются;
- оценка визита ≤ 3 → задача руководителю сервиса;
- расторжение → отмена будущих визитов + визит на демонтаж;
- за 30 дней до конца подписки → «На продлении» + задача (сейчас кнопкой в Настройках, в продакшене — по расписанию).

## Приём заявок с сайтов (готов, не подключён)

```
POST /api/public/leads
X-Site-Key: <ключ сайта из Настроек>
Content-Type: application/json

{ "name": "…", "phone": "…", "company": "…", "area": 120, "message": "…",
  "utm_source": "…", "utm_campaign": "…", "website": "" }
```

Ключ на сайт (`tynys`, `aua`, `vdokh`, `hosh`), в базе — только хеш; разрешённые домены (CORS); `website` — скрытое поле-ловушка (бот получает «успех», лид не создаётся); 10 заявок в минуту с адреса. Ответ: `{ ok, id, duplicate }`. Ключи демо-базы — `data/site-keys.local.json` (не в git).

## Устройство

- Next.js 16 (App Router, Cache Components: статичный каркас + данные потоком за `<Suspense>`), TypeScript, Tailwind 4.
- Drizzle ORM + PostgreSQL. Схема — `src/db/schema.ts`, миграции — `drizzle/`, применяются при первом подключении.
- Сессия — подписанная HMAC cookie (`src/lib/auth.ts`), пароли — scrypt. Каждое действие проверяет роль на сервере и пишется в журнал.
- Деньги — целые тенге, даты — по времени Астаны (UTC+5).
- Каталог ароматов и аппаратов при наполнении взят из общих данных сайтов (`src/db/catalog.json`); дальше источником станет система.
